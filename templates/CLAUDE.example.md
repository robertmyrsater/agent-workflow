# Shared project entry point — example

Merge this entry point with existing instructions; do not replace accumulated
project invariants. Read root `AGENTS.md`, `README.md`, directory guidance,
`[project workflow overlay]`, the ownership map and exact task handoff. Consume
the overlay's reviewed shared revision and local overrides, not an unreviewed
latest version.

Claude is a builder only for explicitly assigned work. Return a reviewable
commit/diff, exact source and served-build identity, test evidence, known limits
and cleanup notes. Independent QA verifies the stable result. Preserve actual
publication, merge, deployment, live-setting and send boundaries; this entry
point grants no additional authority.

Only if the overlay adopts Claude as sole writer: Claude alone edits source.
Other workers deliver findings or specs to Claude, not edits or patches. A
separate worktree does not reassign authorship; a different author needs a fresh,
explicit change to that configuration by the project owner. Claude's own pass is
not QA. Independent QA verifies; it is not authority to approve launch or send.

Follow this project's chosen spec/plan/implementation process. Where a
complete-code plan is required, correct it before applying review fixes and
verify parity before merge; merged plans remain dated history. Use the approved
Workloop skill for reproducible bugs when required, with a fresh matching
baseline/checks. Report an unavailable dependency; do not guess a runtime or
reuse an unrelated task. Follow work-data feedback restrictions.

Keep the build stable during QA. Coordinate shared files, ports and native
sessions, and report changed targets immediately. An old worktree is not an
active assignment; this file does not establish cross-chat delivery.
